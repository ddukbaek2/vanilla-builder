작업

    아직 작업이 없습니다.

        로그
        
			
        
			
        작업을 선택하면 진행 단계와 로그가 보입니다.
        
		
        
	
        

	
        
		
        
			
        설정
        
			
        
				
				
				
        바꾸면 새 포트를 먼저 열어 보고, 성공했을 때만 저장한 뒤 새 주소로 이동합니다.
        
			
        
			
        
				
				
				
        프로젝트별 폴더(<app.id>/builds/<번호>)가 만들어지는 곳. 절대 경로 또는 ~/ 로 시작.
        
			
        
			
        
				
				
			
        
			
        꺼져 있으면 새 업로드를 받지 않습니다. 기본은 꺼짐이며 메뉴 막대에서도 바꿀 수 있습니다.
        
			
			
        
		
        
	
        

	
        
		
        
			
        도움말
        
			
        이 서버가 하는 일
        
			
        vanilla.js 프로젝트의 웹 빌드 결과물과 빌드 명세를 받아 이 Mac 에서 macOS(.dmg)와 iOS(.ipa) 앱을 만들어 줍니다. 저장소 연동 없이 파일을 직접 보내는 원격 빌더입니다. 작업은 큐에 쌓여 한 번에 하나씩 돌고, 중간에 취소할 수 있습니다.
        

			
        1. 올릴 zip 만들기
        
			
        프로젝트에서 npm run build 로 만든 build/web 의 내용을 web/ 폴더로 두고, 그 옆에 build-spec.json 을 넣어 zip 으로 묶습니다. 명세는 zip 루트에 있어야 합니다.
        
			
        project.zip
├── build-spec.json
└── web/
    ├── index.html
    └── ...
        
			
        샘플 build-spec.json 내려받기
        

			
        2. build-spec.json 필드
        
			
        
				
        필드필수설명
        
				
        specVersion필수명세 형식 버전. 지금은 1
        
				
        app.id필수역도메인 형식 식별자. iOS 번들 ID 와 Electron appId 가 됩니다. 예: com.example.mygame
        
				
        app.name필수표시 이름. 산출물 파일명에도 쓰입니다
        
				
        app.version필수X.Y.Z
        
				
        source.webDir필수zip 루트 기준 웹 자산 폴더. index.html 이 있어야 합니다
        
				
        targets.macos선택있으면 macOS 빌드. 지금은 옵션 없이 {}
        
				
        targets.ios.teamIdiOS 시 필수Apple Developer Team ID (10자). Xcode 자동 서명에 씁니다
        
				
        targets.ios.plugins선택웹 코드가 쓰는 Capacitor 플러그인 패키지 목록. 예: ["@capacitor/haptics@^8.0.2"]
        
			
        
			
        옵션이 없는 항목은 고정 기본 동작입니다. macOS 는 1280x720 창 하나에 서명 없는 dmg, iOS 는 Xcode 자동 서명에 App Store Connect 용 ipa 입니다.
        

			
        3. 올리는 방법
        
			
        웹: 작업 화면의 업로드 영역에 zip 을 끌어다 놓거나 클릭해서 고릅니다.
        
			
        API (curl): zip 을 본문으로 그대로 보냅니다. targets 로 명세의 일부 플랫폼만 고를 수 있습니다.
        
			
        curl -X POST "http://이서버주소:포트/api/jobs?targets=macos" \
     -H "Content-Type: application/zip" --data-binary @project.zip
# 응답: { "id": 12 }
        

			
        4. API 목록
        
			
        
				
        메서드경로설명
        
				
        POST/api/jobszip 본문으로 작업 생성. 선택 쿼리 ?targets=macos,ios. 성공 201 { "id" }, 명세 오류 400 { "errors": [...] }
        
				
        GET/api/jobs작업 목록 (최신순)
        
				
        GET/api/jobs/:id상세: 상태, 단계별 상태, 산출물 목록, 오류
        
				
        GET/api/jobs/:id/log로그 텍스트. ?offset=N 이면 N 바이트 이후만
        
				
        POST/api/jobs/:id/cancel취소. 이미 끝났으면 409
        
				
        GET/api/jobs/:id/artifacts/:filename산출물 다운로드
        
				
        GET/api/settings설정 { "port", "workspaceDir" }
        
				
        PUT/api/settings설정 변경. JSON 본문 { "port"?, "workspaceDir"? }
        
			
        
			
        작업 상태: queued → running → succeeded / failed / canceled. 단계는 플랫폼마다 prepare → build → deliver 입니다.
        
			
        완료를 기다리는 흐름: POST /api/jobs → GET /api/jobs/:id 를 상태가 끝날 때까지 폴링 → artifacts 의 파일명으로 다운로드.
        

			
        5. 설정과 서비스
        
			
          
				
        • 설정 화면에서 포트와 워크스페이스 디렉토리를 바꿉니다. 작업 파일은 <워크스페이스>/<app.id>/builds/<번호>/ 에 남습니다.
          • 
				
        • 서버는 macOS launchd 사용자 에이전트로 상시 실행됩니다. 재등록/재시작은 sh scripts/install.sh, 해제는 sh scripts/uninstall.sh.
          • 
				
        • 서버 로그: ~/Library/Logs/vanilla-builder/server.log
